{% trans "How it fits together" %}

{% trans "The mental model. Every piece below exists to answer one question: where does this message go?" %}

{% trans "Sending an SMS through the gateway needs four things wired together, in this order:" %}

1. {% trans "Group" %}→ 2. {% trans "User" %}→ 3. {% trans "SMPP Connector" %}→ 4. {% trans "MT Route" %}→ 📱 {% trans "Delivered" %}
  • {% trans "Group" %} — {% trans "a bucket that users belong to. Create it first because a user must be assigned to one." %}
  • {% trans "User" %} — {% trans "the account that authenticates and sends messages (the “from” side)." %}
  • {% trans "SMPP Connector" %} — {% trans "the outbound link that binds to your provider’s SMSC (the “to the world” side)." %}
  • {% trans "MT Route" %} — {% trans "the rule that connects a message to a connector. Without it, a message has nowhere to go." %}
{% trans "The #1 mistake:" %} {% trans "creating an SMPP connector and stopping there. A connector on its own delivers nothing — you must also add an MT Route that points traffic at it. Otherwise messages fall through to the Default Route (often a stopped connector) and silently go nowhere, even though the panel says “sent”." %}

{% trans "Quick start — first working setup" %}

{% trans "Do these in order. Skipping a step is the usual reason messages don’t arrive." %}
  1. {% trans "Get connection details from your SMS provider: host, port, system-id (username), password (max 8 characters), and your source/sender ID." %}
  2. {% trans "Groups" %} → {% trans "create a group (e.g." %} customers{% trans ")." %}
  3. {% trans "Users" %} → {% trans "create a user inside that group. This is the account you’ll send with." %}
  4. {% trans "SMPP Connectors" %} → {% trans "add a connector with the provider’s host/port/credentials, then press" %} {% trans "to start it. Wait for the status dot to turn" %} {% trans "green (bound)." %}
  5. {% trans "MT Routes" %} → {% trans "add a route that sends your traffic to that connector (see the MT Routes section for the two common patterns)." %}
  6. {% trans "Send SMS" %} → {% trans "send one test message to your own phone." %}
  7. {% trans "Submit Logs" %} → {% trans "confirm a row appears with a success status." %}
{% trans "If the test lands in Submit Logs with a success status and the phone receives it, your pipeline is correct. Everything after that (bulk, more users, more connectors) is just repetition." %}

{% trans "Groups" %} {% trans "create first" %}

{% trans "A container for users. Enable/disable a whole set of users at once." %}

{% trans "When to create:" %} {% trans "before you create any user — every user must belong to a group. One group is enough to start; add more when you want to separate customers, teams, or billing buckets." %}

{% trans "Why it matters:" %} {% trans "disabling a group disables all its users in one action, which is handy for suspending a customer without deleting anything." %}

{% trans "Users" %} {% trans "the sender identity" %}

{% trans "The account that authenticates to send messages, and whose credentials your app or the Send SMS page uses." %}

{% trans "When to create:" %} {% trans "after a group exists, and before you can send anything. Create one user per customer/application that will send SMS." %}

  • uid — {% trans "the user’s unique id (used by routes and filters to identify whose traffic it is)." %}
  • gid — {% trans "the group it belongs to." %}
  • {% trans "username / password" %} — {% trans "the login credentials used when sending." %}
{% trans "Password limit: 8 characters." %} {% trans "SMPP passwords are capped at 8 characters. A longer password is rejected by the form and would otherwise break the connection." %}
{% trans "This “user” is a gateway sending account — it is different from your panel login. Per-user delivery is controlled by MT Routes: to send a specific user’s traffic through a specific connector, pair a User filter with an MT Route (see below)." %}

{% trans "SMPP Connectors" %} {% trans "link to provider" %}

{% trans "The outbound bind to your provider’s SMSC. This is the pipe that carries messages out to the mobile networks." %}

{% trans "When to create:" %} {% trans "one connector per SMS provider/route you buy. Enter the host, port, system-id and password they gave you, then start it." %}

  • {% trans "Press" %} {% trans "to start the connector; it will attempt to bind to the provider." %}
  • {% trans "Watch the status dot — it must be" %} {% trans "green (bound) before it can deliver. See “Status dots”." %}
  • {% trans "Password is capped at 8 characters (provider must issue one that fits)." %}
{% trans "A connector alone does nothing." %} {% trans "Starting a connector only opens the pipe. You still need an MT Route to send traffic into it. This is the step most often forgotten — do the MT Route next." %}

{% trans "HTTP Connectors" %} {% trans "optional" %}

{% trans "Outbound HTTP endpoints (webhooks) on your own servers — used to receive delivery receipts and forwarded inbound messages." %}

{% trans "When to create:" %} {% trans "only if you want the gateway to call your application over HTTP — for example, to push delivery-receipt (DLR) callbacks, or to forward inbound (MO) messages to your app. If you just send outbound SMS, you don’t need this." %}

  • {% trans "Give a connector id, the URL to call, and the HTTP method (GET/POST)." %}
  • {% trans "HTTP connectors are the target of MO Routes (inbound) — the gateway forwards received messages to that URL." %}

{% trans "Filters" %} {% trans "the “which messages” rule" %}

{% trans "A reusable condition that a route uses to decide whether a message matches. Filters are the building blocks of routes." %}

{% trans "When to create:" %} {% trans "when you want a route to apply only to some messages instead of all of them — most commonly “messages from this specific user.”" %}

{% trans "Common filter types:" %}

  • {% trans "User filter" %} — {% trans "matches messages sent by a specific user (uid). This is the one you’ll use most: pair it with an MT Route to give a user their own connector." %}
  • {% trans "Destination-address filter" %} — {% trans "matches by recipient number pattern (e.g. a country prefix), to route different destinations to different providers." %}
  • {% trans "Source/short-message/date-time filters" %} — {% trans "match by sender id, message content, or time window for more advanced routing." %}
{% trans "A filter does nothing by itself — it only takes effect when an MT Route (outbound) or MO Route (inbound) references it." %}

{% trans "MT Routes" %} {% trans "the delivery decision" %}

{% trans "MT = Mobile-Terminated (outbound, going to a handset). This is the rule that decides which connector carries each outgoing message." %}

{% trans "When to create:" %} {% trans "always — immediately after you start an SMPP connector. This is the step that actually makes messages flow." %}

{% trans "Two common patterns:" %}

  • {% trans "Default Route" %} — {% trans "a catch-all (order 0) that sends every message with no more-specific match to one connector. Simplest setup: point the Default Route at your main connector and you’re done." %}
  • {% trans "Static Route + User filter" %} — {% trans "sends one specific user’s traffic to one specific connector. Use this when different customers must go out through different providers." %}
{% trans "How the “sent but never delivered” trap happens:" %} {% trans "if a user has no matching route, their messages fall through to the Default Route. If that Default Route points at a stopped/unbound connector, the message is queued forever — the panel shows “sent”, but it is never delivered and never logged. Fix: give the user a Static Route to a bound connector, or point the Default Route at one." %}
{% trans "Order matters." %} {% trans "Routes are evaluated from highest order down to the Default Route (0). The first one whose filter matches wins. Put specific per-user routes above the catch-all." %}

{% trans "MO Routes" %} {% trans "inbound only" %}

{% trans "MO = Mobile-Originated (inbound — a message someone sends TO your number). This decides what to do with messages you receive." %}

{% trans "When to create:" %} {% trans "only if you receive inbound SMS (two-way messaging, keywords, replies). If you only send, you can ignore MO Routes entirely." %}

{% trans "Why they’re used:" %} {% trans "an incoming message has to be handed somewhere — an MO Route forwards it to one of your HTTP Connectors (your app’s webhook) or to a user. Without an MO Route, inbound messages have no destination and are dropped." %}

{% trans "In short: MT Routes handle what you send out; MO Routes handle what comes in. Most send-only setups need only MT Routes." %}

{% trans "Send a single SMS" %}

{% trans "Best way to test that your whole setup works, end to end." %}
  1. {% trans "Open" %} {% trans "Send SMS" %}.
  2. {% trans "Pick the sending user, enter the recipient number in full international format (e.g." %} +905551234567{% trans "), and type a short message." %}
  3. {% trans "Send it, then open" %} {% trans "Submit Logs" %} {% trans "to confirm a row appears with a success status." %}
{% trans "Always send one single test message after any change to connectors or routes — it’s the fastest way to catch a broken route before a bulk run." %}

{% trans "Send bulk SMS (Campaigns)" %}

{% trans "For sending the same (or templated) message to many recipients." %}
  1. {% trans "Confirm a single test SMS works first — never debug routing during a bulk send." %}
  2. {% trans "Open" %} {% trans "Campaigns" %} {% trans "and create a new campaign." %}
  3. {% trans "Add your recipient list, choose the sending user, and write the message (templates let you personalise per recipient)." %}
  4. {% trans "Launch the campaign, then watch progress and results in the campaign view and in" %} {% trans "Submit Logs" %}.
{% trans "Delivery speed is limited by your provider’s throughput and the connector’s configured rate. A large campaign is sent gradually, not all at once." %}

{% trans "Check logs (Submit Logs)" %}

{% trans "Where you confirm what was sent, and see success vs error for each message." %}

{% trans "Every message that completes gets a row showing the sender, recipient, connector used, timestamp and status. Use it to verify delivery and to investigate failures. You can filter by date and export the results." %}

{% trans "A row only appears once the provider responds." %} {% trans "The log entry is written when the connector gets a response back from the SMSC. If a message was routed to a stopped/unbound connector, there is no response — so no row is written and nothing was actually delivered, even if the panel said “sent”. A missing log row almost always means a routing/connector problem, not a logging problem." %}

{% trans "Status dots (SMPP Connectors)" %}

{% trans "The coloured dot on the connectors page tells you the real bind state — not just whether the service is running." %}
{% trans "Dot" %}{% trans "Meaning" %}{% trans "What to do" %}
{% trans "Green" %} {% trans "Bound — both sides connected. Ready to deliver." %} {% trans "Nothing. This is the healthy state." %}
{% trans "Amber" %} {% trans "Started, but not bound. The service is trying but the provider hasn’t accepted the connection." %} {% trans "Check the password (≤8 chars), that your server IP is whitelisted with the provider, and that host/port are correct." %}
{% trans "Grey" %} {% trans "Stopped. The connector isn’t running." %} {% trans "Press play to start it, then wait for green." %}
{% trans "Hover a dot to see the exact underlying state. Only green means messages can actually go out through that connector." %}
